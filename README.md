# arr-automation

Мелкая автоматика вокруг связки **Sonarr / Radarr / Jellyfin / qBittorrent**, которая
обычно заканчивается тем, что всё руками делаешь ты:

- сам импортируешь загрузки, которые *arr не смог разобрать («требуется ручное управление»);
- сам чистишь фильм из Radarr и с диска после того, как удалил его в Jellyfin;
- сам включаешь на телевизоре приложение Jellyfin, потому что «опять пультом по меню тыкать».

Здесь несколько независимых штук, которые делают это без тебя. Плюс — как свалка моих
правок — сюда же сложены прокси RU-метаданных для Sonarr/Radarr/Prowlarr (русские
названия, описания и постеры + подсказка оригинального названия через LLM).

Собрано под конкретный домашний сервер (Proxmox + Docker, образа `lscr.io/linuxserver/*`,
LG-телевизоры, Jellyfin), но всё переносимо — пути и адреса меняются в пару строк.

## Состав

| Что | Где живёт | Зачем |
|---|---|---|
| `common-scripts/arr-force-import.sh` | хук в Sonarr и Radarr | при залипании загрузки сам разбирает файлы и импортирует их |
| `common-scripts/arr-batch-import.sh` | внутри контейнеров Sonarr/Radarr | то же, но разом по всей очереди — для ручного прогона |
| `common-scripts/media-import.sh` | на хосте | ручной прогон обоих + пересканирование Jellyfin |
| `jelly-arr-reaper/` | свой контейнер, вебхук от Jellyfin | удалил фильм/сериал в Jellyfin → он удалён из *arr и с диска |
| `tv_jelly_launcher/` | свой контейнер, host network | телевизор включился → на нём сам открывается Jellyfin |
| `sonarr-proxy/`, `radarr-proxy/`, `common-arr-proxy/` | контейнеры-прокси перед метадата-API | русские названия, описания и постеры; LLM подсказывает оригинальное имя |
| `prowlarr-proxy/` | контейнер-прокси перед Prowlarr | чистит выдачу поиска релизов от ненужных категорий, нормализует перевод/оригинал/сезон-эпизод |

Пример обвязки — `docker-compose.example.yaml` (ключи заменены на `xxxxxxxx`).

## Как это работает

**1. Залипшая загрузка.** Sonarr/Radarr, не сумев разобрать скачанное, поднимают событие
«Manual Interaction Required». На него висит `arr-force-import.sh`: он спрашивает у
приложения список файлов по `downloadId`, вытаскивает из имени файла сезон и эпизод
(шесть паттернов — от `S01E05` до «7 серия»), находит эпизод в базе и отправляет штатную
команду `ManualImport` с `importMode: move`.

Тот же скрипт можно дёрнуть по всей очереди: `arr-batch-import.sh` выбирает загрузки
в состоянии `warning`, подставляет те же переменные, что дал бы Sonarr, и вызывает
force-скрипт по каждой. `media-import.sh` делает это для обоих приложений и заодно
просит Jellyfin перечитать библиотеку.

**2. Удаление через Jellyfin.** Контейнер `jelly-arr-reaper` слушает `:9100` и принимает
вебхук от Jellyfin. На событие `ItemRemoved` он находит фильм в Radarr по `Tmdb` (сериал
в Sonarr по `Tvdb`) и удаляет его с файлами. То есть чистка происходит там, где удобно:
руками в интерфейсе Jellyfin, а не в двух *arr по очереди.

> Осторожно: по умолчанию `DELETE_FILES=true` — файлы уезжают с диска. Поставьте
> `DELETE_FILES=false`, если хотите, чтобы удаление было только из *arr.

**3. Запуск Jellyfin на телевизоре.** `tv_jelly_launcher` пингует телевизоры из списка
`TVS` и, поймав переход «выключен → включён», подключается к webOS, при необходимости
проходит сопряжение (первый раз телевизор спросит разрешение, ключ сохраняется в `tv_key/`)
и запускает приложение Jellyfin.

## Установка

1. Скопировать `common-scripts/` и каталоги контейнеров рядом с остальными compose-проектами
   (в примере — `/opt/docker-compose/{common-scripts,configs/jelly-arr-reaper,configs/tv_jelly_launcher}`):

   ```bash
   install -d -m 755 /opt/docker-compose/common-scripts
   install -m 755 common-scripts/*.sh /opt/docker-compose/common-scripts/
   cp -r jelly-arr-reaper tv_jelly_launcher /opt/docker-compose/configs/
   ```

2. Прописать сервисы из `docker-compose.example.yaml` в свой compose и подставить вместо
   `xxxxxxxx`:

   - `RADARR_API_KEY`, `SONARR_API_KEY` — *Settings → General → API Key* в самих приложениях;
   - `JELLYFIN_TOKEN` в `media-import.sh` — *Dashboard → API Keys* в Jellyfin.

3. Хук в Sonarr и Radarr: *Settings → Connect → добавить → Custom Script*, триггер
   **On Manual Interaction Required**, путь `/config/scripts/arr-force-import.sh`.
   Скрипты должны быть исполняемыми (в репозитории они уже с `+x`).

4. Вебхук в Jellyfin: *Dashboard → Plugins → Webhooks → Add Generic Destination*, URL
   `http://jelly-arr-reaper:9100/webhook`, тип уведомления — **Item Removed**.
   Порт наружу открывать не нужно: Jellyfin ходит к контейнеру по docker-сети.

5. `tv_jelly_launcher`: подставить свои телевизоры в `TVS` (`имя=адрес,имя=адрес`).
   Первый запуск потребует подтверждения сопряжения на самом телевизоре.

## Ручное использование

```bash
# импорт залипших в конкретном приложении (изнутри контейнера)
docker exec sonarr /config/scripts/arr-batch-import.sh sonarr
docker exec radarr /config/scripts/arr-batch-import.sh radarr

# то же + пересканирование Jellyfin (с хоста, от root)
/opt/docker-compose/common-scripts/media-import.sh
```

Лог скриптов — `common-scripts/log` (лежит рядом, пишут оба приложения). Если он
перерастает 1 МиБ, предыдущий уезжает в `log.1`.

## Переменные окружения

`jelly-arr-reaper`:

| Переменная | Значение |
|---|---|
| `RADARR_URL`, `RADARR_API_KEY` | адрес и ключ Radarr (`http://radarr:7878`) |
| `SONARR_URL`, `SONARR_API_KEY` | адрес и ключ Sonarr (`http://sonarr:8989`) |
| `DELETE_FILES` | `true` — удалять с файлами, `false` — только из базы |

`tv_jelly_launcher`:

| Переменная | Значение |
|---|---|
| `TVS` | `имя=адрес` через запятую, например `кухня=192.168.1.32,спальня=192.168.1.30` |
| `PING_INTERVAL` | период опроса телевизоров, секунды (по умолчанию 4) |
| `DEBUG_PING` | `true` — логировать каждый пинг |
| `JELLYFIN_MATCH` | подстрока для поиска приложения в списке установленных (по умолчанию `jellyfin`) |

## Что стоит знать

- `arr-batch-import.sh both` имеет смысл только при запуске на хосте. Изнутри контейнера
  API-ключ читается из его `/config/config.xml`, а порт — из его же localhost, поэтому
  чужое приложение оттуда недоступно. Запускайте по одному (как `media-import.sh`) или с хоста.
- Реапер ищет фильм в Radarr перебором полного списка библиотеки, а не через
  `/movie/lookup/tmdb`: у Radarr в ответе lookup-эндпоинта нет библиотечного `id`, а удаляем
  мы именно по нему. У Sonarr точечный `/series/lookup?term=tvdb:<id>` поле `id` отдаёт.
- Импорт идёт с `importMode: move` — файл переносится, а не копируется, как и при импорте
  руками в интерфейсе.
- Запуск Jellyfin на телевизоре выполняется в отдельном потоке: сопряжение может ждать
  подтверждения до 60 секунд, и без этого основной цикл всё это время не опрашивал бы
  остальные телевизоры.

## Прокси RU-метаданных

Sonarr и Radarr ищут по оригинальным названиям: на запрос «Грызня» нужный сериал находится
с трудом, а описания и постеры приходят английские. Прокси встают между приложением и его
метадата-сервером (`links` в compose) и правят это:

- `sonarr-proxy` подменяет `skyhook.sonarr.tv`, `radarr-proxy` — `api.radarr.video` и
  `radarr.servarr.com`, `prowlarr-proxy` — сам Prowlarr (поиск релизов);
- ответы обогащаются через TMDb: русское название, описание, постер. Постеры кладутся в
  свой кэш `cached_images/`, картинки раздаются через путь `tmdb_proxy`;
- при `ENABLE_LLM=true` прокси спрашивает LLM оригинальные названия по русскому запросу и
  ставит её вариант в начало выдачи — так находятся транслиты (`слоу хорсес` → `Slow
  Horses`) и опечатки, а результаты исходного запроса остаются ниже;
- ответы TMDb и ответы LLM кэшируются, «TMDb не знает» помнится 90 дней, число
  одновременных обращений к TMDb ограничено.

Общий код обоих прокси (кэши, выбор и подстановка постера, прокси картинок, вызов LLM) —
`common-arr-proxy/arr_common.py`, монтируется read-only в `/common`.

Для обогащения нужен ключ TMDb — передаётся переменной окружения `TMDB_API_KEY`
(берётся бесплатно: themoviedb.org → Settings → API). В коде его нет.

### Сертификаты и бандл

Приложение ходит в прокси по HTTPS на имя проксируемого хоста, поэтому в каталоге прокси
нужен свой самоподписанный `cert.pem`/`key.pem`, а `ca-bundle.crt` собирается как
«системные корни + этот сертификат» — так приложение ему доверяет. Как это делается —
`sonarr-proxy/rebuild-cert-bundle.sh`. В репозитории сертификатов и ключей нет намеренно.
